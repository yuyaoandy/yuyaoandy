01 背包，完全背包，多重背包这些都是简单的 DP 入门题，但是其实背包还是有很多变化的。

从最简单的开始：

**01 背包：**

有 $N$ 个物品，每个物品有一个重量 $W_i$ 和价值 $V_i$。

每个物品**最多只能拿一次**，问在重量不超过 $M$ 的情况下能够取得的最大价值。

考虑 DP，设 $F_{i,j}$ 表示考虑到了前 $i$ 个物品，重量为 $j$ 时的最大价值。

可以得到 $F_{i,j}=\max{(F_{i-1,j},F_{i-1,j-W_i}+V_i)}$。

因为 $F_{i,j}$ 只和 $F_{i-1,j}$ 与 $F_{i-1,j-W_i}$ 有关，所以可以倒着枚举 $j$ 从而将 $i$ 一维去掉。

```cpp
for(int i=1;i<=N;++i)
	for(int j=M;j>=W[i];--j)
		F[j]=max(F[j],F[j-W[i]]+V[i]);
```

时间复杂度 $O(NM)$。

**完全背包：**

有 $N$ 个物品，每个物品有一个重量 $W_i$ 和价值 $V_i$。

每个物品**可以拿任意次**，问在重量不超过 $M$ 的情况下能够取得的最大价值。

仍然考虑 DP，但是我们不需要枚举每个物品拿了多少次再做 01 背包，只需要将做 01 背包时的第二层循环倒过来。

```cpp
for(int i=1;i<=N;++i)
	for(int j=W[i];j<=M;++j)
		F[j]=max(F[j],F[j-W[i]]+V[i]);
```

因为此时 $F_{j-W_i}$ 已经考虑过了**选择若干次物品 $i$ 的情况**，所以直接转移就相当于在此基础上多选择了一次物品 $i$。

时间复杂度 $O(NM)$。

完全背包的经典结论：如果 $M>\max W_i^2$ 那么可以一直取性价比最高的物品将 $M$ 缩减到 $\max W_i^2$，也就是我们不可能取超过 $\max W_i$ 个性价比并非最高的物品。

证明：考虑将最终取出来的所有物品排成一排，并对 $W_i$ 做前缀和。则由抽屉原理相邻 $\max W_i$ 个数中，有前缀和相等的两个位置，将这两个位置之间的物品都换成性价比最高的一定不劣。

**多重背包：**

有 $N$ 个物品，每个物品有一个重量 $W_i$ 和价值 $V_i$。

每个物品**可以拿 $T_i$ 次**，问在重量不超过 $M$ 的情况下能够取得的最大价值。

我们可以将每一个物品拆成 $T_i$ 个，然后问题变为 01 背包了。

```cpp
for(int i=1;i<=N;++i)
    for(int k=1;k<=T[i];++k)
		for(int j=M;j>=W[i];--j)
			F[j]=max(F[j],F[j-W[i]]+V[i]);
```

这样做时间复杂度是 $O(M\sum T)$。

这显然不够优美，因为这 $T_i$ 个物品完全相同啊。

我们考虑用尽量少的物品代替这 $T_i$ 个物品使得这些物品仍然能够起到 $T_i$ 个物品的效果。

考虑二进制。

众所周知，选取 $2^0,2^1,2^2,\cdots ,2^k$ 中的若干个相加就能够表示出 $0\sim (2^{k+1}-1)$ 中的所有数。

这给了我们启发，我们首先找到 $2^{k+1}-1\le T_i$ 的 $k$。

然后将 $2$ 的幂次个物品“聚合”成一个。

也就是体积价值分别为： $(2^0W_i,2^0V_i),(2^1W_i,2^1V_i),(2^2W_i,2^2V_i),\cdots (2^kW_i,2^kV_i)$。

然后我们再加入一个 $((T_i-2^{k+1}+1)W_i,(T_i-2^{k+1}+1)V_i)$ 的物品。

可以发现，这样恰好能够一个不漏且一个不多地表示选择 $0\sim T_i$ 个物品的情况。

这样再做 01 背包，由于拆成的物品数量是 $O(N\log T)$ 级别的，所以时间复杂度为 $O(NM\log T)$。

上面这种优化方法叫做**二进制分组**。

当 $\sum T$ 一定的时候，这种做法的复杂度可以做到 $O(M\sqrt{T})$。

还有另外一种优化方法：

在朴素的实现中，我们需要在 $F_{j-kW_i}+kV_i,(k\le T_i)$ 中找到最大值。

而这非常像滑动窗口找最大值的过程，于是我们可以使用**单调队列优化**。

一旦一个 $j-kW_i$ 被弹出，那么它将永远不可能成为最优的转移点。

```cpp
inline void init(int* F,int ww,int cc,int tt){
    //往 F 数组里面添加重量为 ww，价值为 cc，数量为 tt 的物品
	memset(G,0,sizeof(G));
	for(int j=0;j<cc;++j){
		int hd=1,tl=1;q[tl]=0;
		for(int i=1,p=j+cc;p<=d;i++,p+=cc){
			while(hd<tl&&q[hd]<i-tt)++hd;G[p]=F[q[hd]*cc+j]+(i-q[hd])*ww;
			while(hd<=tl&&F[q[tl]*cc+j]+(i-q[tl])*ww<=F[p])--tl;
			q[++tl]=i;
		}
	}
	memcpy(F,G,sizeof(G));
}
```

接下来是一些例题：

[烹调方案](https://www.luogu.com.cn/problem/P1417)

比较有意思的一题，每个物品的价值并不固定，这就需要一些贪心小技巧。

直接去算背包的话，由于顺序上的问题，可能取不到最优解。

考虑如果我们确定了要选择哪一些物品，那么我们一定会按照某种最优的顺序做。

而求出这个顺序是一个经典的贪心。（可以在贪心相关内容里看到）

通过交换调整法可以得到，我们一定会先去烹饪 $\frac{B_i}{C_i}$ 比较大的菜。

所以说将所有的物品按照 $\frac{B_i}{C_i}$ 进行排序之后，我们只会按顺序依次烹饪这些菜，此时直接做背包是对的。

```cpp
int T,n;
struct node{
	int a,b,c;
}A[100];
inline bool cmp(node X,node Y){
	return 1ll*X.b*Y.c>1ll*Y.b*X.c;
}
long long f[120000],Mx;
int main(){
	cin>>T>>n;
	for (int i=1;i<=n;++i)cin>>A[i].a; 
	for (int i=1;i<=n;++i)cin>>A[i].b;
	for (int i=1;i<=n;++i)cin>>A[i].c;
	sort(A+1,A+n+1,cmp);
	for (int i=1;i<=n;++i)
		for (int j=T;j>=A[i].c;--j)
			f[j]=max(f[j],f[j-A[i].c]+A[i].a-1ll*j*A[i].b),Mx=max(f[j],Mx);
	cout<<Mx;
	
}
```



[消失之物](https://www.luogu.com.cn/problem/P4141)

与背包相关的计数问题，要求支持撤销一个数的贡献。

要求计数比较容易，只需要将 $F_j=\max({F_j,F_{j-W_i}+V_i})$ 改成 $F_j=F_j+F_{j-W_i}$。

撤销一个数的贡献就考虑我们加入数的时候产生的贡献。

对最终的 $F$ 从前往后进行 $F_j=F_j-F_{j-W_i}$ 即可，感觉不难。

当然，你也可以用多项式方法爆艹。

对于一般的背包，我们就不能够像这样直接撤销了。

一般撤销一个数需要对前缀做一个背包，后缀做一个背包，然后再合并起来。

[Jumping sequence](https://www.luogu.com.cn/problem/AT_abc221_g)

感觉是挺简单的一个题，首先我们发现直接去 DP，$X$ 坐标和 $Y$ 坐标的贡献不独立，因此需要做二维的背包，不可接受。

这一类二维平面坐标或者**曼哈顿距离**有关的题常常能够使用转坐标系求切比雪夫距离解决。

具体地，我们将坐标轴逆时针旋转 $45^\circ$，也就是对于一个点做如下变换 $(X,Y) \to (\frac{X+Y}{2},\frac{X-Y}{2})$。

这时候我们发现对于一步行走 $A_i$ 距离的操作，我们可以选择行走 $(\frac{A_i}{2},\frac{A_i}{2}),(\frac{A_i}{2},-\frac{A_i}{2}),(-\frac{A_i}{2},\frac{A_i}{2}),(-\frac{A_i}{2},-\frac{A_i}{2})$。

此时 $X$ 和 $Y$ 坐标独立（无论是 $X$ 取 $+\frac{A_i}{2}$ 还是 $-\frac{A_i}{2}$，$Y$ 都可以任意取 $\pm \frac{A_i}{2}$）

然后将容量和物品体积共同的 $\frac{1}{2}$ 提出来原问题就转化为两次背包，依次容量是 $X+Y，X-Y$，选择一个物品需要 $A_i$ 容量，不选将会 $-A_i$ 容量，问是否能够达到 $X+Y$ 和 $X-Y$ 的容量。

再略加转化，默认一个物品不选（这样将一个物品由不选改为选就会有 $2A_i$ 的贡献），就可以转化为比较标准的背包了。

但是这样还是过不去，这时由于我们只需要求解可行性，所以容易发现我们的 DP 数组中其实都是 $01$。

发现背包需要的操作无非是整体 $\text{or}$ 和左移，这些操作都是 $\text{bitset}$ 能完成的，我们用 $\text{bitset}$ 替换 DP 数组，就可以方便地求出有无解了。

时间复杂度是 $O(\frac{nD}{w})$。 

但是本题要求输出方案，我们可以额外记录一个 $from$ 数组，表示 $i$ 这个体积最终是由 $i-A_{from_i}$ 这个体积转移过来的，这样就可以最后递归下去求解答案了。

但是 $from$ 数组肯定是不能 $\text{bitset}$ 优化的，但是我们只需要求一组合法解，而 $from_i$ 在第一次被更新之后就能说明存在体积为 $i$ 的合法解。于是我们可以使得每一个 $from_i$ 只被更新一次。

也就是说每次加入一个物品 $A_i$，我们需要知道新增的合法位置。

也就是说新的 $\text{bitset}$ 和老的 $\text{bitset}$ 之间的变化，这个可以使用 $\text{xor}$ 操作。

而取出 $\text{bitset}$ 中的元素可以使用 $\text{\_Find\_first}$ 和 $\text{\_Find\_next}$ 解决，这样遍历一个 $\text{bitset}$ 的时间复杂度是 $O(\frac{len}{w}+c)$ 的其中 $c$ 是 $\text{bitset}$ 里面值为 $1$ 的元素个数。

由于我们保证了每一个 $from_i$ 只会被更新一次，所以 $\sum c=O(D)$，因此总的时间复杂度是 $O(\frac{nD}{w}+D)$ 的，可以通过。

```cpp
	cin>>n>>X>>Y,X=X+Y,Y=X-Y*2;
	for(int i=1;i<=n;++i)cin>>A[i],val+=A[i];
	if(max(abs(X),abs(Y))>val)cout<<"No\n",exit(0);
	X+=val;Y+=val;
	if((X&1)||(Y&1))cout<<"No\n",exit(0);X>>=1,Y>>=1,BA[0]=1;
	for(int i=1,lim=max(X,Y);i<=n;swap(BA,BB),++i){
		BB=BA|(BA<<A[i]),BA^=BB;
		for(int j=BA._Find_first();j<=lim;j=BA._Find_next(j))frm[j]=i;
	}
	if(!BA[X]||!BA[Y])cout<<"No\n",exit(0);cout<<"Yes\n";
	while(X)res[frm[X]]|=2,X-=A[frm[X]];while(Y)res[frm[Y]]|=1,Y-=A[frm[Y]];
	for(int i=1;i<=n;++i)cout<<"LDUR"[res[i]];
```

[[SDOI2017] 苹果树](https://www.luogu.com.cn/problem/P3780)

卡常题。

这题有一个限制就是如果取了一个儿子节点，就必须取父亲节点，然后还能够免费取一条链.

这类和树有关的背包问题一般都考虑按照 DFS 序把树拍平。

首先考虑枚举这一条免费的链（容易发现一定会取到叶子节点为止），那么这棵树将会被分成两部分。

设 $F_{i,j}$ 表示考虑了 DFS 序（为了方便，这里使用出栈序）小于等于 $i$ 的数，体积为 $j$ 的答案。

其中我们在 DFS 序进一个节点的时候加入 $a_i-1$ 次，出一个节点的时候再加入 $1$ 次。

这样我们的 $F_{i,j}$ 就能既包含到根节点的那一条链，还包含树左边的那一部分（图中蓝色和红色部分）。

![](https://cdn.luogu.com.cn/upload/pic/45237.png) 

（从 SovietPower✨ 那偷的图）

$G_{i,j}$ 则表示右边这一块区间中取了 $j$ 个的最大价值（可以将所有节点的儿子顺序翻转一下做）。

至于如何求这个 $F$ 和 $G$。

对于每一个节点，如果它的子树不选，那么它的儿子节点也不能够选，$F_{dfn_u-siz_u}\to F_{dfn_u}$。

当然也可以进子树，枚举当前节点 $u$ 选择的次数并且用单调队列优化做到 $O(nk)$。（这个是树上非常经典的操作）

不难发现 $F_{i,j}$ 和 $G_{i,j}$ 拼在一起，在加上免费取的那一条链就形成了整个贡献，合并的过程可以做到 $O(n k)$，注意常数。

[Shopping](https://www.luogu.com.cn/problem/P6326)

这里介绍一种可以对每一个子树求答案的做法。

我们当然可以对于每一个儿子节点都求出答案然后将他们合并起来加上根节点求出每个子树的答案，但是由于两个背包合并需要 $m^2$ 非常不优秀，我们需要更低时间复杂度的做法。

考虑树剖，每次先解决重链里面的子树答案，并利用重儿子的答案来求父亲节点的答案，对于轻子树，我们每次 dfs 进去重新求答案，不利用已经求出的子树答案。

可以发现，每个节点到根路径上最多只有 $\log n$ 次作为轻儿子，所以每个节点被重新求答案的次数也是 $O(\log n)$。

总的时间复杂度也就是 $O(nm\log n)$。

[PermuTree (hard version)](https://www.luogu.com.cn/problem/CF1856E2)

二进制分组和 bitset 优化可行性背包和树剖的综合应用。

首先背包只需要求解可行性的时候显然可以使用 $\text{bitset}$ 优化。

这样可以有 $\frac{1}{w}$ 的小常数。



对于这一题，首先观察到我们要做的就是对于每一个节点，将它的儿子节点划分成两个集合，使得这两个集合的大小差最小。



要求大小之差最小，是经典的可行性背包，设 $F_i$ 表示大小为 $i$ 是否可行，转移也简单。

但是注意到这个吓人的 $10^6$ 范围，这样就算对于一个节点也显然过不去，即使使用了 bitset 优化。

这时候就需要使用前面二进制分组的结论了。

将相同大小的儿子并在一起当做同一类物品，然后进行二进制分组，这样就最多有 $\sqrt{siz}$ 个物品，对于一个节点的复杂度就是 $O(\frac{siz\sqrt{siz}}{w})$ 。

但是我们需要对于所有节点都做一次，因此还是没有办法通过。

考虑树剖并分析性质：

如果重儿子的大小 $\ge \frac{siz_u}{2}$ 那么我们肯定我们要将其他的节点放在一个集合里，重儿子单独成一个集合。

否则我们才需要做上面的背包。

这样时间复杂度最多是 $T(n)=2T(\frac{n}{2})+\frac{n\sqrt{n}}{w}$。

应用主定理可以得到时间复杂度为 $O(\frac{n\sqrt{n}}{w})$，可以通过。
